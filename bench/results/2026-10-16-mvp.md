# Native real SPD MVP: measured single-node result

The native CPU implementation is robustly nondominated on all **115 frozen
case/workload groups**, separately for elapsed solver-phase time versus peak
host RSS and for whole-workflow process CPU time versus peak host RSS. Each
group has an explicitly measured native ordering/thread configuration for which
every measured external configuration is excluded as a possible dominator over
the retained five-trial ranges. This is empirical evidence on this corpus and
host, not universal leadership or an AUTO-selection claim.

Rechecking the earlier retained best-known external training/HB baseline also
leaves all 60 corresponding groups robustly nondominated. The historical
baseline report is archived alongside the current comparison.

The stronger same-comparator match/beat gate is unchanged: **109 pass, four
indeterminate, two time/memory tradeoffs**. A nondominated point need not beat
an existing point on both axes. The two tradeoffs are the training/held-out
large-2D eight-RHS workloads: native one-thread takes 28.84 ms and 21.66 MiB,
versus MUMPS one-thread 21.52 ms and 24.35 MiB. The indeterminate strict groups
are the smallest band's refactor and large-2D cold one-RHS cases, in both
coefficient variants. All remain robustly nondominated.

## Corpus, accuracy and accounting

- Eleven synthetic SPD cases: three bandwidth-four bands, three anisotropic
  2D grids, three 3D grids, plus the externally calibrated 128x128 and 24x24x24
  scaling cases. Held-out coefficients retain the graph and change the values.
- HB/bcsstk09 is the unmodified archived structural stiffness matrix: n=1083,
  full nnz=18437. Its source, byte hash and interpretation are frozen in
  `../fixtures/bcsstk09.json`.
- Five workloads: cold one/eight RHS, retained-pattern changed-value refactor,
  implicit JVP/VJP, and warm-runtime factorization. Five fresh-process trials
  at 1/2/4/8/16 requested physical cores for all six CPU configurations.
- **17,250 selected CPU trials and 300 actual-device GPU trials all pass.**
  Ordinary invocation limits remain one second: observed maxima are 0.823 s
  among retained CPU comparisons and 0.961 s for CUDA. The final native sweep
  adds 5750 successful remeasurements; superseded trials remain archived.
- Original-matrix backward error is below 1e-12; observed CPU maximum is
  1.66e-15. Known tangents and adjoint identities are checked independently.
  This is backward-error evidence, not a rigorous forward-error certificate.

Elapsed admission uses factor+solve, refactor+solve, or factor+primal+JVP+VJP
as appropriate. Whole-workflow CPU is user+system across all parent threads,
plus separately measured helper CPU, and includes fixture/setup, checking,
cleanup and the first warmup factor where applicable. These quantities must
not be called phase CPU time. RSS is Linux post-exec process peak; UMFPACK
parent/helper peaks remain separate and are never summed. Its parent RSS is
only a lower bound on unknown aggregate memory in the nondominance test.

## Implementation and GPU limits

The CPU path uses simplicial and compact supernodal Cholesky, AMD/ND ordering,
elimination-subtree tasks, direct dense intersections, generated rank-one
updates and bounded-work generated schedules. The mathematical leaves and
their derivatives come from retained FortSym definitions. Larger contractions
lower to BLAS. Context-owned mapped symbolic scratch releases actual pages
after analysis. Profiling and rejected variants are recorded in
`2026-10-16-profiling.md`; the operating rules are in `../../AGENTS.md`.

Low-work generated schedules save about 2.8 MiB of cold RSS. Some small reused
3D phases cost an extra 0.1–0.17 ms; the final corpus still satisfies both
nondominance audits. The implementation does not claim a novel Cholesky
algorithm. AUTO continues to retain its external-backend policy.

CUDA factorization is native and verified on device 0. It retains panel/update
storage and refactor contexts, then downloads factors for CPU solves. It is
**not performance admitted**: large-3D warm factor+solve is 296.7 ms and
575.3 MiB host RSS, versus the CPU configurations above. Attributed device
storage excludes unreported vendor/driver pools. A Nsight Systems trace sees
68.7 MB of CUDA allocations, including vendor storage, on the profiled smaller
case; this is not an exact total device-memory measurement. Hardware counters
were unavailable (ERR_NVGPUCTRPERM); permissions were unchanged.

## Verification and reproduction

Fourteen focused CPU/benchmark CTests and fourteen CUDA/native CTests pass;
each test is under one second. The final Fo lane passes its four-target gate,
then stops before measurement. Independent graph elimination, known solutions,
offset/padding, block RHS, permutation, failure recovery and derivative oracles
remain active. The full test suite was not run. Fo lint reports two preexisting
unused imports and nine deliberate temporaries in fixture/oracle expressions;
no production short-circuit diagnostic was reported.

Host: Ryzen 9 5950X, GNU 16.2.1, Fortran `-O3 -march=znver3`, OpenBLAS 0.3.34
with one BLAS thread, SuperLU 7.0.1, SuiteSparse 7.14.1/AMD 3.3.4, MUMPS 5.9.1,
Intel oneMKL 2026.0 PARDISO in an isolated executable, CUDA 13.4 and RTX 5060 Ti.
This measures Intel oneMKL PARDISO, not Panua. Physical-core affinity and thread
settings are fixed; the shared host and GPU are not exclusive. Observed ranges
are not confidence intervals. Optional ordering/BLAS dependencies remain
external libraries; no MPI execution is introduced.

Raw trials, hashes, build configurations, commands, profiler evidence and the
full report are retained in
`~/code/sparse-dev/benchmarks/2026-10-16-native-mvp/`. Compact per-case evidence,
plot numeric inputs and plot manifests are retained here. PNGs are ephemeral
slopbox uploads and are not committed. Reproduce with `../run_spd.py`,
`../report_spd.py` and `../plot_spd.py` as documented in `../README.md`.
